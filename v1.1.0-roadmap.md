# Cue Bear v1.1.0 Roadmap

## Goals
- Prepare UI for iPhone version (responsive, scalable design)
- Add more control and customization for users
- Modernize navigation with main menu system

---

## Feature List

### 1. Regular Mode Plus/Minus Transport Controls
**Description:**
- Create a new transport capsule for Regular mode (like GO capsule in Cue mode)
- Pill-shaped, vertical/upright oval, divided in the middle
- **+** button (top half) triggers NEXT cue in list
- **-** button (bottom half) triggers PREVIOUS cue in list
- Matches GO button visual style (floating capsule with material background)
- **DRAGGABLE** - User can position it anywhere on screen
- **TOGGLE ON/OFF** - User can show/hide it

**Benefits:**
- Navigate cue list without entering Cue mode
- Quick access to prev/next without looking at list
- Consistent with GO button design language
- Customizable position (won't block important controls)

**Toggle Location Options:**
1. **Settings Menu** - Global app setting (always on/off)
2. **Main Menu** - Quick toggle in hamburger menu ("Show Plus/Minus Controls")
3. **Title Bar Toggle** - Small icon button (like transport icon)
4. **Long-press gesture** - Long-press capsule to show hide option
5. **Control Area Menu** - Near other transport controls

**Recommendation:** Main menu toggle ("Show Plus/Minus Capsule" checkbox)
- Easy to find
- Doesn't clutter title bar
- Pairs well with other view options

**Dragging Implementation:**
- Same pattern as GO capsule (DragGesture)
- Save position in UserDefaults (global, not per-project)
- Constrain to safe area (avoid menu bars, control area)
- Free-form positioning

**Visual Design:**
- Vertical pill (upright oval)
- **↑** Up arrow (top half) - triggers NEXT cue
- **↓** Down arrow (bottom half) - triggers PREVIOUS cue
- NO text, NO cue name/number display
- Just arrows for minimal, clean design

**Behavior (same as GO capsule):**
- Success flash on triggered cue item
- Auto-scroll cue list to show triggered item
- Haptic feedback on tap
- Scale animation on press

**Decided:**
- ✅ Default position: **bottom  -right corner** (right edge, below title bar)
- ✅ Position saved globally (draggable by user)
- ✅ No cue name/number shown (just arrows)
- ✅ This is NEW - no existing transport to replace in Regular mode
- ✅ Toggle via main menu checkbox

### 2. Simplified Title Bar
**Description:**
- Reduce number of title bar buttons to minimum
- Goal: Make UI scalable for iPhone (small screen)
- Move non-essential buttons to main menu

**Current Title Bar Buttons:**
- Project name (dropdown/menu)
- Regular/Cue mode toggle
- Connection status icon (broadcast)
- USB/WiFi chips (when available)
- Edit button
- + button (add controls)

**DECIDED - Must Stay in Title Bar:**
- ✅ **Connection status** (broadcast icon + USB/WiFi chips) - Critical for users to see connection state
- ✅ **Edit button** (Edit Cue List) - Important workflow control
- ✅ **Project name** (center) - Changes to three-dot menu button
- ✅ **Regular/Cue toggle** (mode selector)

**Changes:**
- Replace Project name dropdown → Three-dot menu (consolidates project actions)
- + button (add controls) → Move to control area footer or menu

**Final Minimal Title Bar:**
- Three-dot menu (left) - replaces project dropdown
- Regular/Cue toggle (center or right)
- Connection status icons (right)
- Edit button (right)

### 3. MIDI CC Filter/Exclude List
**Description:**
- Allow users to exclude specific MIDI CC numbers from auto-assignment
- UI: Text field + "Add" button
- Creates chips with X to remove
- Excluded CCs won't be auto-assigned
- User tries to manually assign filtered CC → show popup warning

**Behavior:**
- **Auto-assign:** SKIPS filtered CC numbers completely
- **Manual assign:** Shows confirmation popup ("CC 7 is typically used for Volume. Are you sure you want to assign it?")

**Use Cases:**
- Protect CC #1 (Mod Wheel)
- Protect CC #7 (Volume)
- Protect CC #11 (Expression)
- Protect CC #64 (Sustain Pedal)
- Protect CC #120-127 (System messages)

**Recommended Default Filters:**
1. CC 1 - Modulation Wheel
2. CC 7 - Volume
3. CC 11 - Expression
4. CC 64 - Sustain Pedal
5. CC 120-127 - Channel Mode Messages

**UI Explanation Text:**
"Protect standard MIDI controls from auto-assignment. This prevents accidentally overriding essential functions like volume, sustain pedal, and modulation wheel that your other gear or software may already be using."

**Implementation Ideas:**
- Settings/Main menu section: "MIDI CC Filter"
- Explanation text above (2 lines, gray text)
- Text field: "Enter CC number (0-127)"
- "Add" button next to text field
- Chip display below: [1 ✕] [7 ✕] [64 ✕] [120-127 ✕]
- Persist in UserDefaults (global setting)
- Support ranges: "120-127" creates single chip for range

**Decided:**
- ✅ Global (app-wide) setting
- ✅ Applies to CC only (not Note assignments)
- ✅ Warning popup on manual assignment attempt
- ✅ Auto-assign completely skips filtered numbers

### 4. Main Menu System
**Description:**
- Replace multiple title bar buttons with modern main menu
- **DECIDED:** Three-dot menu (⋯) opening iOS-style context menus/sheets

**Menu Style:**
- **Three-dot icon** (⋯) in top-left
- Taps to open native iOS menu (like Mail, Safari)
- NOT a slide-out drawer
- Context menu style with sections

**Why Context Menus (Not Drawer):**
- ✅ More modern iOS design pattern
- ✅ Faster to access (one tap, not slide)
- ✅ Doesn't cover content
- ✅ Native iOS component (Menu/contextMenu)
- ✅ Works better on iPhone small screens

### 5. Appearance/Color Scheme Menu
**Description:**
- Let users customize app color scheme
- System options: Light, Dark, Auto (system)
- Custom accent colors?
- Preset themes?

**Options to Consider:**
1. **System Only:** Light, Dark, Auto (simplest)
2. **Accent Color:** Choose primary accent color (currently blue)
3. **Preset Themes:**
   - Classic Blue (current)
   - Professional Gray
   - Warm Orange
   - Cool Purple
   - Stage Red
4. **Full Custom:** Let users pick all colors (complex)

**Good Idea?**
- ✅ PRO: User personalization, accessibility (colorblind users)
- ✅ PRO: Match tour branding (red for rock shows, etc.)
- ⚠️ CON: More maintenance, testing in multiple color schemes
- ⚠️ CON: Can look unprofessional if poorly chosen

**Recommendation:** Start with system Light/Dark/Auto + accent color picker. Preset themes in future update.

### 6. Custom Colors for Buttons/Faders/Cues
**Description:**
- Add color picker to Create/Edit sheets
- Users can assign custom colors to:
  - Control buttons (background/accent)
  - Faders (fill color)
  - Cue list items (background/text)

**Use Cases:**
- Color-code sections: Red for intro, Blue for verse, Green for chorus
- Organize by instrument: Brass = gold, Strings = brown
- Visual hierarchy: Important cues in bright colors
- Accessibility: High-contrast for stage visibility

**UI Design Ideas:**
- Segmented control: "Default" / "Custom"
- When Custom selected: Show color picker
- Preset color palette (8-10 common colors)
- Or full iOS color picker wheel

**Implementation Considerations:**
- Store color in ControlButton/Song model (new property)
- Apply as background, stroke, or both?
- Ensure text remains readable (contrast checking)
- Dark mode compatibility

**Questions:**
- Should color be background or accent/stroke only?
- Show color in list view or only on the button itself?
- Allow gradient/multiple colors or single color only?

## Technical Considerations

### iPhone Adaptation Strategy
- Use adaptive layouts (GeometryReader, size classes)
- Collapse split view to tabs or navigation stack
- Title bar becomes navigation bar on iPhone
- Transport controls float or dock to bottom
- Control area scrolls or uses paging

### Backwards Compatibility
- All features should be optional/additive
- Existing projects should open without migration
- Default values for new properties (color = nil means use accent)

### Testing Requirements
- iPhone SE (smallest screen)
- iPhone Pro Max (largest screen)
- iPad Mini (smallest iPad)
- iPad Pro 13" (largest iPad)
- Both orientations (portrait/landscape)
