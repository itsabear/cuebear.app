# Cue Bear v1.0.9 Changelog

## Bug Fixes

### 1. USB chip visibility fix
- USB chip now only appears when Bridge app is running (not just when cable is connected)
- Modified `ConnectionManager.swift` to check `connectedComputerName != nil` instead of `isUSBCableConnected`

### 2. USB chip timing fix
- USB chip now appears immediately when connection is established (synchronized with "Connected" status)
- Added `checkUSBBridgeAvailability()` call immediately after handshake completes in `ConnectionManager.swift:678`

### 3. Song library + icon behavior
- Plus icon now stays visible but turns grey when song is already in cue list (instead of disappearing)
- Modified `ControlSubviews.swift:381-404` to show greyed-out icon with `.disabled()` state

### 4. Button preview sizing
- Button previews in create/edit mode now match the actual button sizes in control area
- Changed preview dimensions in `ContentView.swift:1388-1427`:
  - Regular buttons: 156×72 (matching 2.17:1 aspect ratio)
  - Small buttons: 72×72 (1:1 ratio)

### 5. Dark mode support
- Comprehensive dark mode implementation across all views
- Changes in multiple files:
  - `Components.swift`: Transport controls, shadows
  - `ControlSubviews.swift`: Performance rows, badges
  - `ContentView.swift`: Control buttons, faders, delete icons
  - `TransportPreviews.swift`: Preview components
- Replaced hardcoded `.white` with `Color(uiColor: .systemBackground)`
- Replaced hardcoded `.black` with `Color.primary`
- Button icons explicitly use `.accentColor` to maintain blue in all modes
- All shadows use `Color.primary.opacity()` instead of `.black.opacity()`

### 6. Delete button improvements
- Delete X buttons in edit mode are now easier to tap:
  - Circle size: 22×22 → **30×30** (36% larger)
  - Icon size: 10pt/12pt → **13pt**
  - Hit target: 60×60 → **70×70**
  - Opacity: 0.85 → **0.9**
  - Better positioning: Moved further to top-left corner
- Changes in `ContentView.swift`:
  - Regular buttons: offset (-25, -25) → **(-32, -32)**
  - Faders: offset (-25, -25) → **(-32, -32)**
  - iPad tiles: offset (-23, -23) → **(-30, -30)**

### 7. Save & Add Another MIDI type preservation
- When creating a Note control and clicking "Save & Add Another", the next control now correctly defaults to Note (instead of always resetting to CC)
- Fixed in `ControlSubviews.swift:1154-1177`:
  - Now preserves `savedKind` before resetting form
  - Sets `kind = savedKind` to maintain MIDI type
  - Calls `autoAssignMIDI(for: savedKind, ...)` with preserved type
- Note: Control buttons/faders were already working correctly

## New Features

### 8. Smart auto-assign with channel increment
- **Without global mode**: When reaching CC/note 127, automatically moves to next channel and continues from 0
  - Allows up to **2,032 controls** (127 × 16 channels) instead of just 127
- **With global mode**: Shows error popup when limit reached
  - Message: "You've reached the maximum of 127 controls in Global MIDI Channel mode. Turn off Global MIDI Channel mode to continue auto-assigning on additional channels."
- Applies to all creation methods:
  - +Button
  - +Fader
  - +Cue list
  - Save & Add Another
- Implementation:
  - Created new `autoAssignMIDI()` function in `ContentView.swift:916-981` and `ControlSubviews.swift:1011-1066`
  - Added alert states in both files
  - Updated all `.onChange` handlers and preset functions

## UI Improvements

### 9. Projects menu reordering
- "New Project" button now appears first in the Actions section, above "Save"
- Modified `ControlSubviews.swift:781-788` (CBProjectsSheet)
- Improves workflow by prioritizing new project creation

### 10. Edit mode tap behavior for cue list and song library
- **Normal mode (not editing)**:
  - Context menu removed from cue list items
  - Tapping cue list items triggers/cues the song (existing behavior)
  - Song library items can be browsed but not edited via tap
- **Edit mode**:
  - Tapping any cue list item opens the edit sheet
  - Tapping any song library item opens the edit sheet
  - Context menu removed (no long-press menu)
- Implementation in `ControlSubviews.swift`:
  - Added `isEditing: Bool` parameter to `CBPerformanceList` (line 9)
  - Added `isEditing: Bool` parameter to `CBPerformanceRow` (line 57)
  - Modified tap gesture behavior (lines 79-96) to call `onRename()` in edit mode
  - Changed from `.simultaneousGesture` to `.gesture` (line 149) to give tap handler priority
  - Removed context menu entirely (line 150)
  - Updated song library tap logic (line 413): `onTap: (!isEditing || batchMode) ? nil : { onRename(row.song) }`
- Modified `ContentView.swift:1871` to pass `isEditing` state to `CBPerformanceList`

### 11. Preserve unsaved changes in cue edit sheet
- Cue list edit behavior now matches button/fader edit behavior
- When you edit a cue and dismiss the sheet (tap outside), your unsaved changes are preserved
- Reopening the same cue shows your previous edits, allowing you to continue editing
- Changes are cleared when you Save or Delete (fresh start for next edit)
- Implementation in `ControlSubviews.swift` (CBAddEditCueSheet):
  - Added `lastEditingSongID` state variable to track which cue is being edited (line 876)
  - Modified `.onAppear` to only preset form if editing a different cue (lines 964-971)
  - Modified `.onChange(of: editingSong)` to only preset when cue ID changes (lines 972-980)
  - Clear `lastEditingSongID` after Save (line 1172) and Delete (line 945)

### 12. Enhanced cue list tap feedback
- Made successful cue tap feedback more noticeable and snappier for better user experience
- Changes in `ControlSubviews.swift` (CBPerformanceRow):
  - Flash now works in both regular mode (triggering MIDI) and cue mode (cueing songs)
  - Haptic feedback upgraded from `.light` to `.medium`
  - Flash animation duration optimized to 0.20s - noticeable but quick (line 167)
  - Feedback now triggers in cue mode when cueing a new song (previously only in regular mode)
  - Press-down animation response time reduced from 0.18s to 0.10s for snappier feel (line 151)
  - Flash and haptic now trigger immediately on finger release via `.onChange(of: isPressed)` instead of `.onEnded` for instant visual feedback with no delay (lines 153-159)
  - When dragging (scrolling), no flash occurs - just smooth "safe unpress" animation back to full size

### 13. Swipe-to-delete for song library items in edit mode
- Added swipe left to delete functionality for song library items when in edit mode
- Only available in edit mode (not in batch select mode)
- Supports full swipe for quick deletion
- Implementation in `ControlSubviews.swift` (CBLibraryColumn):
  - Added `.swipeActions` modifier with delete button (lines 423-431)
  - Delete button only appears when `isEditing && !batchMode`
